# 제2장: 인가 등급과 위험도 매트릭스

## 2.1 리소스 접근 모드(`AccessMode`)

CAP 1.0은 호스트 리소스 작업에 대해 직교하는 네 가지 접근 모드(`AccessMode`)를 정의한다. 접근 모드 간에는 **계층적 포함 관계가 존재하지 않는다**(예: `write` 권한이 `read`나 `configure`를 자동으로 포함하지 않음).

| 접근 모드 | 동시성 잠금 의미론 | 규범적 정의 |
|-----------|--------------------|-------------|
| `read` | 공유 읽기 잠금(Shared) | 센서 텔레메트리, 장치 상태 또는 설정 스냅샷을 읽기만 하며 호스트 내부 상태나 외부 물리 환경을 변경하지 않는 작업 |
| `write` | 배타적 잠금(Exclusive) | 호스트 저장소 데이터 수정, 제어 레지스터 기록 또는 펌웨어 이미지 기록을 수행하는 작업 |
| `execute` | 배타적 잠금(Exclusive) | 물리 액추에이터 구동, 외부 통신 발신 또는 시스템 프로세스 호출을 유발하는 작업 |
| `configure` | 배타적 잠금(Exclusive) | 호스트 보안 정책, 제어 루프 계수(비행 제어기 PID 이득 등) 또는 권한 경계 구성을 변경하는 작업 |

런타임 세션 동시성 제어에서 동일 호스트 리소스에 대한 복수의 `read` 작업은 병렬로 허용되지만, `write`, `execute`, `configure` 작업은 반드시 배타적 잠금을 독점해야 하며(**MUST**) 다른 모든 동시 작업과 상호 배제된다.

## 2.2 작업 위험도(`Criticality`) 전순서 관계

CAP 1.0은 모든 호스트 작업을 잠재적 위험 수준에 따라 엄격한 전순서를 갖는 4단계로 분류한다.

$$\texttt{routine} (0) < \texttt{sensitive} (1) < \texttt{high} (2) < \texttt{critical} (3)$$

- **`routine`(일상)**: 완전히 가역적이며 프라이버시 유출이나 물리적 손상 위험이 없는 일상적 읽기 또는 제한된 멱등 작업(예: 온도 텔레메트리 읽기).
- **`sensitive`(민감)**: 관리 대상 파라미터 조정, 민감 상태 조회 또는 유계 보상 절차가 존재하는 상태 변경(예: 제어기 이득 조정).
- **`high`(고위험)**: 외부 세계에 비가역적 결과를 초래하거나 물리 기구를 작동시키거나 대량 외부 발신을 수행하는 작업(예: 화물칸 물리 걸쇠 해제). 온라인 파생 바인딩과 작업별 `Human Prime` 명시적 확인이 요구된다.
- **`critical`(치명적·최고위험)**: 복구 불가능한 데이터 파기, 하드웨어 벽돌화(브릭) 위험 또는 중대한 물리 안전 위험을 초래하는 작업(예: 보안 영구 삭제, ESC 저수준 펌웨어 플래싱). `G1` 전용 게이트로 가장 엄격히 제한된다.

## 2.3 Faying 자율·재석 등급(`FayingGrade`)

CAP 평가기는 `Faying-Protocol`이 정의하는 5단계 세션 등급을 소비한다(`Faying-Protocol` 참조).

- **`G0`**: `Human Prime`(인간 프라임)의 직접 긴급 인수 상태(최우선 선점 상태이며 `Fay` 자율 실행 상태가 아님)
- **`G1`**: `Human Prime` 실시간 강력 재석 바인딩 상태(최고 인가 강도이며 `critical` 작업을 실행할 수 있는 유일한 등급)
- **`G2`**: `Human Prime` 감독 동반 상태
- **`G3`**: 일반 수임 자율 상태
- **`G4`**: 제한된 백그라운드 자율 상태(최저 인가 강도)

`CapGrant.min_grade`(값 범위 `G1`–`G4`)에 대한 인가 강도 순서는 다음과 같이 정의된다.

$$\text{Strength}(\texttt{G1}) = 4 > \text{Strength}(\texttt{G2}) = 3 > \text{Strength}(\texttt{G3}) = 2 > \text{Strength}(\texttt{G4}) = 1$$

현재 세션 등급이 $\text{Strength}(\texttt{session\_grade}) < \text{Strength}(\texttt{grant.min\_grade})$이면 평가기는 반드시 요청을 거부하고(**MUST**) `E_GRADE_INSUFFICIENT`(`2002`)를 반환해야 한다.

---

## 2.4 3차원 등급 판정 매트릭스(`FayingGrade × AccessMode × Criticality`)

`session_grade`가 `G1`–`G4`에 속하고 `grant.min_grade`를 충족하는 전제하에, CAP 평가기는 다음 보수적 매트릭스에 따라 `(session_grade, requested_mode, effective_criticality)` 조합을 판정해야 한다(**MUST**).

| 유효 위험도 (`effective_criticality`) | `G1`(실시간 강재석) | `G2`(감독 동반) | `G3`(일반 자율) | `G4`(제한 백그라운드) |
|---------------------------------------|---------------------|-----------------|-----------------|-----------------------|
| **`critical`** | `read` / `write` / `execute` / `configure` 허용(**제4장 확인 게이트 필수**) | **`DENY`** | **`DENY`** | **`DENY`** |
| **`high`** | 인가된 모든 모드 허용(**제4장 확인 게이트 필수**) | 인가된 모든 모드 허용(**제4장 확인 게이트 필수**) | **`DENY`** | **`DENY`** |
| **`sensitive`** | 인가된 모든 모드 허용 | 인가된 모든 모드 허용 | `read` / `write` / `execute`만 허용(**`configure` 엄금**) | **`DENY`** |
| **`routine`** | 인가된 모든 모드 허용 | 인가된 모든 모드 허용 | 인가된 모든 모드 허용 | `read` / `execute`만 허용(**`write`·`configure` 엄금**) |

### 매트릭스 핵심 보안 불변식

1. **`critical`의 `G1` 전용 철칙**: 유효 위험도가 `critical`인 모든 작업은 `G2`, `G3`, `G4` 세션에서 `human_confirmation` 첨부 여부와 관계없이 반드시 `DENY` 및 `E_GRADE_INSUFFICIENT`(`2002`)를 반환해야 한다(**MUST**).
2. **`G3` 설정 격리**: `G3` 세션에서 `sensitive` 작업에 대해 `configure` 모드를 요청하면 반드시 `DENY` 및 `E_GRADE_INSUFFICIENT`(`2002`)를 반환해야 한다(**MUST**).
3. **`G4` 쓰기·설정 금지**: `G4` 세션에서는 `routine` 작업에 대한 `read` 또는 `execute`만 허용되며, 모든 `write`, `configure` 또는 `routine`을 초과하는 작업은 반드시 `DENY` 및 `E_GRADE_INSUFFICIENT`(`2002`)를 반환해야 한다(**MUST**).
